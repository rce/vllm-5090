# 2026-09-06 — Nemotron 3.5 Lightning 30B-A3B

`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4`, 21.6 GB. MoE, 30B total /
3B active, but a **Mamba hybrid** (`NemotronHForCausalLM`, `nemotron_h`) rather
than the gated-DeltaNet hybrid the Qwen3.x models use. Text-only — no vision
tower. Native context 1,048,576; capped at 65,536 here to match the Qwen3.6
profile so the sweeps compare directly.

## It is faster than Qwen3.6-35B-A3B, and it is not close at low concurrency

Same workload, same `MAX_NUM_SEQS=32`, same prompt. Total tok/s:

| Concurrency | Nemotron 3.5 Lightning | Qwen3.6-35B-A3B | delta |
| ---: | ---: | ---: | ---: |
| 1 | **363** | 259 | +40% |
| 2 | **486** | 376 | +29% |
| 4 | **837** | 709 | +18% |
| 8 | **1,293** | 1,180 | +10% |
| 16 | 1,873 | 1,861 | +1% |
| 32 | 2,653 | 2,546 | +4% |

Per-stream decode at concurrency 1 is 387 tok/s against Qwen's 277. TTFT p50 is
0.047 s against 0.067 s. The advantage is largest for a single caller and has
essentially evaporated by concurrency 16 — both models saturate the same card at
roughly the same ceiling, which is what you would expect when both activate ~3B
parameters per token.

## The KV pool is the real headline: 1,497,245 tokens

Four times Qwen3.6's 370,189, at a *lower* `--gpu-memory-utilization` (0.80 vs
0.85). That is the Mamba hybrid doing what Mamba does — most layers carry a
constant-size recurrent state instead of a KV cache that grows with sequence
length. vLLM reports 22.85x max concurrency at the full 65,536 context, against
5.65x for Qwen3.6.

For long-context or many-caller work that headroom matters more than the
throughput numbers above. It is also the one dimension where none of the sweeps
here stress it — worth a 16K-prompt sweep to see whether the advantage survives.

## Two sm120 problems with the recipe's flags

There is no `rtx_5090` profile upstream, so the profile starts from the
`rtx_pro_6000` override — same sm120 architecture, more VRAM. Two flags in it do
not work on this card:

**`--linear-backend marlin` fails outright.** `ValueError: Failed to find a
kernel that can implement the ScaledMM linear layer ... To apply FP8 Marlin on
high-capability GPUs, please set VLLM_TEST_FORCE_FP8_MARLIN=1`. Dropped it;
auto-selection picks the native NVFP4 path, which is what the Qwen NVFP4
profiles use anyway. Forcing the env var was not attempted — the auto path is
the one that should be fast here.

**The "fast SSM cache" feature is half unusable.** Its stochastic rounding emits
a PTX `.rs` instruction that does not exist on consumer Blackwell:

```
ptxas ... error : Feature '.rs' not supported on .target 'sm_120a'
ptxas fatal   : Ptx assembly aborted due to errors
```

So `--enable-mamba-cache-stochastic-rounding` and `--mamba-cache-philox-rounds`
are dropped. The `--mamba-ssm-cache-dtype float16` half is kept and works. The
feature appears to assume datacenter Blackwell. Whether the fp16 cache alone
gives most of the benefit is unmeasured.

Also worth noting: the reasoning parser is `nemotron_v3`, not `qwen3`. The
entrypoint used to hardcode the Qwen parser; it is now per-profile. Tool calls
use `qwen3_xml`, same as the Qwen MoE.

## What this does not say

**Nothing about quality.** Nemotron is faster and roomier; whether it is as good
is not something these numbers can answer, and the comparison is not even
like-for-like — Qwen3.6-35B-A3B is a VLM and this is text-only. If image input
matters, this model is not a replacement regardless of throughput.

That gap is the reason for the eval-harness research in
`2026-09-06-eval-harness-research.md`.

## Worth trying next

- A 16K-prompt sweep, where the 4x KV pool should actually show up.
  (Update: a 4K-*output* sweep does show it — +25% over Qwen3.6 at 32
  streams; see `2026-09-06-long-generation.md`.)
- Spec decoding. The recipe lists three modes — built-in MTP, a DSpark hybrid
  speculator, and a DFlash diffusion drafter — and `dspark` is its default.
  None tried; DSpark needs a separate draft checkpoint.
- `--mamba-cache-mode align` instead of `none`, since prefix caching interacts
  with it and the generic recipe command prefers `align`.
  (Update: moot — vLLM overrides `none` to `align` when prefix caching is on,
  and the cache works: ~80% hits, flat TTFT over a 19K-token agent loop. See
  `2026-09-06-agentic-baseline.md`.)
